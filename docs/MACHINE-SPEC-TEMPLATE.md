# 新機種シミュレーター 仕様テンプレート

新しいパチンコ機種のシミュレーターを作る際、このテンプレートを埋めてClaudeに渡せば、
ブレスト・設計をほぼスキップして実装計画に進める。

**前提（共通フォーマット・毎回そのまま流用するもの）**:
- UIシェル: ヘッダー3行構成（回転数／収支+回転数レート+大当たり総回数／詳細ボタンで展開する内訳パネル）、
  操作パネル（START・一括回転・演出設定・退店）、演出ON/OFF設定モーダル、精算画面、履歴欄、
  当たり演出の全画面モーダルシステム。実装は `pachinko-simulator-garo` を参照実装とする。
- ファイル構成: `index.html`/`style.css`/`script.js`/`calc.js`（純粋関数＋node:testでTDD）
- 払い出し実値/表示値の変換式（後述セクション5）

以下、機種ごとに埋める項目。

## 4. RUSH/LT構造タイプ

以下のカタログから選ぶか、当てはまらない場合は新パターンとして定義する。

### カタログ

**① ST型（グールデカ/ghoul型）**
電サポ（ST）回数（例: 130回）が設定され、その間に当たれば回数がリセットされて延長する。
次回当たりの保証はないが、当たり続ける限り理論上無限に連チャンしうる。ST中の当選確率は
通常時とは別レートで抽選される。

**② 確変型（牙狼/garo型）**
大当たり後、次回大当たりがほぼ濃厚な状態（LTモード）に入る。LT中は抽選のたびに
「継続」か「終了」かが決まり、終了に割り振られた確率を引くと必ず通常時に戻る
（＝有限の終了率で必ずいつか終わる、無限ループではない一本道の連チャン構造）。

**③ 1種2種型（キン肉マン型、未実装・要詳細化）**
1種（デジタル抽選）で当たりを引くと、2種（権利物）側の「保留チャージ権利」を獲得する。権利数に応じて後続の大当たり有無・
大小・最低保証が変動する方式。実装時に都度、権利の消費/獲得ルールを具体的に詰める必要がある。

### この機種で採用するタイプ

- タイプ: ①／②／③／新規（新規の場合は上記と同じ粒度で構造を記述する）
- 連チャン数の表示方法: 採用したタイプの標準表示に従う（① なら電サポ残り回数、② なら連チャン数カウント、
  ③ なら権利残り数など）

## 5. 払い出し表（実値/表示値は自動導出）

**フォーマット共通の基準値**（`pachinko-simulator-garo`から導出。機種によって実際の基準玉数が
異なる場合はここを上書きする）:

- 1カウントあたりの表示発数: 15発
- 1ラウンドあたりのカウント数: 10カウント
- 1ラウンドあたりの投入コスト（実質減算分）: 10発

→ **1ラウンド = 150発（表示） / 140発（実質）**
　（表示 = ラウンド数 × 150、実質 = ラウンド数 × 140）

機種固有で入力するのは **ラウンド数だけ**でよい:

| ボーナス名称 | ラウンド数 | 表示発数（自動算出） | 実質発数（自動算出） |
|---|---|---|---|
| 例: 1500ボーナス | 10 | 1500 | 1400 |
| 例: 7500ボーナス | 50 | 7500 | 7000 |
| 例: チャージ | 2 | 300 | 280 |
| （機種固有のボーナスを追記） | | | |

両方OFFで告知のみのモード＝先祝モード相当）をそのまま使うかどうか。

- 対象にする演出: （セクション3の予告演出のうち、ON/OFF切り替え対象にするもの。通常は全部）
- 両方OFF時のモード名・告知文言: （例: 「先祝モード」「🎉 先祝告知発生！」。機種テーマに合わせて変更可）

## 使い方

1. このテンプレートを埋める（画像素材の登録は不要。画像は実装時に別途用意する）
2. 埋めた内容をClaudeに渡し、`pachinko-simulator-garo`を参照実装として新規プロジェクトを立ち上げる
3. 通常の brainstorming → 設計書 → 実装計画 → 実装 の流れに乗せる（このテンプレートが設計書の大部分を代替する）
