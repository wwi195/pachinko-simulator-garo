# ヘッダー再構成・演出ON/OFF機能・LTリザルト表示修正 設計書

## 背景・目的

`pachinko-simulator-garo`（グールデカ形式リニューアル版）に対する3件の改修:

1. ヘッダー行2（持ち球/投資/収支）の表示優先度を変更し、空いたスペースに回転数レートを追加する
2. 牙狼剣・牙狼保留の演出をそれぞれON/OFFできるようにし、両方OFF時は「先読みモード」に切り替わる機能を追加する
3. LT終了リザルト画面の「合計獲得」表示が実際の払い出しと異なる基準（1400ベース）になっているのを、1500ベースの表記に統一する

いずれも**ゲームの確率・払い出し経済（S.balls・収支計算）には一切影響しない**。表示・演出の見せ方のみを変更する。

## ① ヘッダー行2の再構成

現状（`index.html` `.hrow2`）:

```
持ち球: 0発   投資: 0円   収支: 0円
```

変更後:
- **収支**をメイン表示（大きいフォント）に格上げ
- **持ち球・投資**は同サイズで小さく表示
- 空いたスペースに**「1000円あたりの回転数」**（固定値・現状は17回転）を追加
- 行3（大当たり回数の行）に現在ある `17回転/千円`（`.fee-block`）表示は行2に一本化するため**削除**し、重複させない

レイアウト順は「持ち球（小）／投資（小）／収支（大・メイン）」＋「1000円あたりの回転数」を1行に収める。具体的なCSS配分（フォントサイズ・並び順）は実装時に`style.css`の`.money-*`系クラスを流用・拡張する。

## ② 演出ON/OFF設定（「演出設定」機能）

### UI

- 操作パネル（START / 1万円分回す / 退店ボタンのエリア）に「演出設定」ボタンを追加する
- 他の操作ボタンと同様、`_busy`中（演出モーダル表示中）は無効化する（`lockAll()`の対象に追加）
- 押すと既存のモーダルシステム（`#ov`/`#mb`/`showM`/`closeM`）を使って設定パネルを表示する
- パネル内には「牙狼剣演出：ON/OFF」「牙狼保留演出：ON/OFF」の2つのトグルボタンがあり、押すとその場でパネルの表示を再描画して即座に状態を反映する（`closeM()`しない）
- 「閉じる」ボタンでパネルを閉じる
- デフォルトは両方ON（現状と同じ挙動）
- トグル状態はページの再読み込み（精算後の「もう一度遊ぶ」を含む）でリセットされる（永続化しない、現状の他の状態と同様）

### 確率モデル（最重要・不変条件）

**「図柄揃い」の当選確率（牙狼剣・牙狼保留合算）は、ON/OFFの組み合わせに関わらず常に一定**:

```
WIN_RATE = C.P_HW + C.P_SW  （= 1/874.8 + 1/874.8 ≒ 1/437.4、表示上「約1/440」）
```

この値は絶対に変更しない。変わるのは「その当選を、どちらの演出でどのくらいの頻度で見せるか」だけ。

**両方ON（現状のまま）:**

既存の `T1`〜`T4` をそのまま使用。挙動は一切変更しない。

**片方だけON（例：牙狼剣のみON、牙狼保留OFF）:**

OFFにした側の当選チャンス（当選確率分）はONの側に完全に合流する。ただし、ONの側が本来持っている信頼度（牙狼剣40%／牙狼保留80%）はそのまま維持し、その信頼度に収まるように「演出の発生頻度（見せる頻度）」を逆算する。

```
confidence = 0.40（牙狼剣のみON） または 0.80（牙狼保留のみON）
winBoundary   = WIN_RATE                  // 当選判定はここまで（不変）
totalBoundary = WIN_RATE / confidence     // 演出が発生する範囲全体（ここまでがハズレ込みの発生ゾーン）
```

例：牙狼剣のみON（confidence=0.40）の場合、`totalBoundary = WIN_RATE / 0.40 ≒ 1/175`。つまり約1/175の頻度で牙狼剣演出が発生し、そのうち40%が当たり・60%がハズレとなる（トータルの当選確率は約1/440のまま）。牙狼保留のみONの場合は逆に発生頻度が下がる（confidence=0.80のため）。

この計算により、`tmHolderPre`/`tmSwordPre`内の「信頼度 80%」「信頼度 40%」の表示文言は**一切変更不要**（この確率モデル自体が、その信頼度表示が常に正しくなるように発生頻度を逆算する設計のため）。

片方だけONの場合、演出テンプレート・遊技履歴の文言（`牙狼剣`/`牙狼保留`）はすべて**生き残っている側の名義**で表示・記録する（例：牙狼剣のみONなら、元は牙狼保留側の当選確率だった分も含めて「牙狼剣」として表示・記録される）。`doHit()`に渡す`type`引数もONの側（`'holder'`または`'sword'`）で統一する。

チャージ演出（`C.P_CH`）の絶対確率・発生位置の"幅"は常に不変。牙狼剣/牙狼保留ゾーンのサイズが変わった分だけ、チャージゾーンの開始位置（オフセット）がスライドするのみ。

**両方OFF（先読みモード）:**

牙狼剣・牙狼保留の合算ゾーン自体は現状の`T1`〜`T4`と**完全に同じ範囲・同じ当落判定**を使う（発生頻度の再計算はしない — このモードでは信頼度表示という概念自体が存在しないため）。ただし見せ方を変える:

- 当たり（`r<T1` または `T2<=r<T3`）の場合: 「🎉 先祝告知発生！」（画像なし）のモーダルを表示 → その後、通常の図柄揃い演出（`doHit`）に入る
- ハズレの場合: **モーダルを一切表示しない。遊技履歴にも何も記録しない。** 完全にサイレントに次へ進む（「1万円分回す」の連続実行中も止まらず継続する）

## ③ LTリザルト画面の獲得表示を1500ベースに統一

### 現状の問題

`C.B15=1400`（表示上「1500ボーナス」）、`C.B75=7000`（表示上「7500ボーナス」）が実際の払い出し・収支計算に使われる値。LT終了リザルト画面（`tmLTEnd`）などで、この実数値（1400/7000）がそのまま「獲得◯◯発」として表示されており、見出しの「1500」「7500」という表記と数値が食い違っている。また「合計獲得」はLT中の増分のみ（初当たり分の1500を除外）を表示している。

### 修正方針

- **収支計算・S.balls・出玉率などの実際の経済指標は完全に不変**（`C.B15=1400`, `C.B75=7000`のまま。award()の呼び出し・引数も一切変更しない）
- **表示専用の定数**を新設: `C.DISP_B15=1500`, `C.DISP_B75=7500`
- 以下の箇所の表示を、実数値ベースから表示専用定数ベースに置き換える:
  - `tmExWin`（獲得 ${C.B75}発 → ${C.DISP_B75}発）
  - `tmExLose`（獲得 ${C.B15}発 → ${C.DISP_B15}発）
  - `tmLTGaro`（獲得 ${C.B75}発 → ${C.DISP_B75}発）
  - `tmLTVic`（獲得 ${C.B15}発 → ${C.DISP_B15}発）
  - `tmLTEnd`の「🎯 図柄揃い」行（${C.B15}発 → ${C.DISP_B15}発）
  - `tmLTEnd`の「終了ボーナス（獲得 ${C.B15}発）」（→ ${C.DISP_B15}発）
- **合計獲得の計算方法を変更**: 現状は`runBalls - C.B15`（LT中の増分のみ、実数値ベース）だが、これを「初当たり分を含めた全体合計・表示専用定数ベース」に変更する。`doHit()`内で`runBalls`（実経済用、変更しない）とは別に、表示専用の累計`nominalGain`を新設し、初当たり時に`C.DISP_B15`で初期化、以降イベントごとに`C.DISP_B75`または`C.DISP_B15`を加算していく。`tmLTEnd`にはこの`nominalGain`を渡す。
- 遊技履歴（`addH`）内の「→ 計${runBalls}発」も同様に`nominalGain`ベースの表示に変更する（doHit内の該当2箇所: LT成功時・極限バトル敗北時、および非突入時）

### 検算（設計の妥当性確認）

例：初当たり(1500) → 極限バトル勝利(7500) → LT1回目で転落(1500):

```
nominalGain = 1500（初期化）
            + 7500（極限勝利、tmExWin）
            + 1500（LT1回目・終了/転落）
            = 10500
```

ユーザーが期待する結果と一致する。
