# 牙狼7500 疑似遊技シミュレーター 設計書

公開URL: https://wwi195.github.io/pachinko-simulator-garo/
リポジトリ: https://github.com/wwi195/pachinko-simulator-garo

## 概要

`garo7500-repo`（単一HTMLファイル完結型の牙狼7500シミュレーター）の確率・払い出しロジックと演出画像はそのままに、表示形式（統計ヘッダー・操作ボタン・履歴欄）を `pachinko-simulator-ghouldeka` と同じ形式に作り替えたバージョン。軍資金選択・機種選択・プレミアムプランは廃止し、固定レートでページを開くと即プレイ開始する。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | 画面構造（ヘッダー・操作パネル・履歴欄・モーダル） |
| `style.css` | 見た目（グールデカ形式のダーク＋ゴールド基調） |
| `script.js` | ゲームロジック・状態管理・DOM更新 |
| `calc.js` | 純粋関数（`floor500`／`computeShuushi`／`computeMergedRange`）。`node:test`でユニットテスト済み（`test/calc.test.js`、5テスト） |
| `images/` | 演出画像10点（読み込み失敗時はテキストプレースホルダーに自動フォールバック） |

ビルド不要。`index.html`をブラウザで開くだけで動作する。

## 遊技条件（固定・変更不可）

- 交換レート: 等価（4円投資 / 4円換金）
- 回転数レート: 17回転/千円（固定、選択不可）
- 軍資金上限: なし（グールデカと同様、無制限に投資可能）
- 回転数上限（閉店処理）: なし。プレイヤーが「退店する」を押すまで継続
- 1000円あたりの獲得発数: 250発（`BPK`）→ 1回転の消費発数 = 250/17 ≈ 14.71発
- 「1万円分回す」ボタン: 170回転（17回転/千円 × 10）を一括実行

## 確率・払い出し仕様

| 事象 | 確率 | 備考 |
|---|---|---|
| 牙狼保留 出現→当たり | 1/874.8 | 信頼度80%（保留出現時の当選率） |
| 牙狼保留 出現→ハズレ | 1/3499.2 | |
| 牙狼剣 出現→当たり | 1/874.8 | 信頼度40%（剣出現時の当選率） |
| 牙狼剣 出現→ハズレ | 1/583.2 | |
| ガロチャージ | 1/1749.9 | 獲得+280発、大当たりではない |

- 牙狼保留・牙狼剣どちらも「出現」自体は総合当たり確率とは別に、各々の出現＋ハズレ込みの頻度で発生する（保留は約1/700、剣は約1/350の頻度で出現）。
- **図柄揃い当選確率（保留・剣の当たり合算）は常に一定＝ 1/874.8 + 1/874.8 ≒ 1/437.4（約1/440）**。これは演出ON/OFF設定（後述）を変えても絶対に変化しない不変条件。

### 大当たり後の流れ

```
図柄揃い（保留 or 剣 の当たり）
  └ 極限7500バトル突入判定（50%）
      ├ 突入なし（50%）→ 通常時継続
      └ 突入（50%）
          └ 極限バトル勝敗判定（50%）
              ├ 敗北（50%）→ 1500ボーナスで通常時に戻る
              └ 勝利（50%）→ 7500ボーナス + 魔戒CHANCE LT突入
                  └ LTループ（連チャン中は毎回抽選）
                      ├ 25%: GOD OF GARO（7500継続）→ ループ継続
                      ├ 51%: 1500継続ボーナス → ループ継続
                      └ 24%: 1500終了 → LT終了、通常時に戻る
```

### 実際の払い出し（経済）と画面表示（呼称）の違い

「1500ボーナス」「7500ボーナス」という呼称に対し、実際にゲーム内部で加算される発数は端数がある（実機の「見なし出玉」的な演出のため）。**内部の収支計算・持ち球は常に実払い出し値を使用し、変更不可。画面表示（各演出の「獲得◯◯発」表記、LT終了リザルトの合計獲得）のみ、呼称通りの1500/7500ベースの数値で統一している。**

| 呼称 | 実際の払い出し（経済用） | 画面表示（呼称ベース） |
|---|---|---|
| 1500ボーナス系（図柄揃い初当たり／極限敗北／LT中1500継続／LT終了） | 1400発 | 1500発 |
| 7500ボーナス系（極限勝利／LT中GOD OF GARO継続） | 7000発 | 7500発 |
| ガロチャージ | 280発 | 280発（呼称・実値とも同じ） |

LT終了リザルト画面の「合計獲得」は、初当たり分（1500）を含めた連チャン全体の合計を、上記の表示ベースで積み上げた値を表示する（例: 初当たり1500 → 極限勝利7500 → LT1回目で終了1500 の場合、合計獲得は10,500発）。

## 演出ON/OFF設定（先祝モード）

操作パネルの「⚙ 演出設定」ボタンから、牙狼剣・牙狼保留それぞれの演出をON/OFFできる（デフォルトは両方ON。ページ再読み込みでリセット、設定は永続化しない）。

- **両方ON（通常）**: 従来通り、保留・剣それぞれ別々に出現・判定される。
- **片方だけON**: OFFにした方の当選チャンスはON側に完全に合流するが、ON側が元々持つ信頼度（保留80%／剣40%）は維持される。総合の図柄揃い当選確率（約1/440）は変えず、その信頼度に収まるよう演出の発生頻度を逆算する（例: 剣のみONだと「1/440の当選を40%の的中率で見せる」ため、演出自体の発生頻度は上がる。保留のみONだと逆に下がる）。
- **両方OFF（先祝モード）**: 保留・剣の発生判定自体は通常時と全く同じレンジ・確率を使うが、見せ方が変わる。ハズレ時は演出・履歴記録とも一切なしの完全サイレント（「1万円分回す」中も止まらず継続）。当たりの時だけ「🎉 先祝告知発生！」（画像なし）の告知が出て、その後は通常の図柄揃い演出に合流する。

## 画面構成

### ヘッダー

1. **行1（回転数）**: 今回転数／累計回転数
2. **行2（常時表示・メイン統計）**: 収支（大きく強調表示）／1000円あたりの回転数（17回転、固定値）／大当たり総回数
3. **行3（詳細）**: 「▶ 詳細を見る」ボタンを押すと、以下が展開表示される
   - 持ち球／投資
   - 図柄揃い合計（内訳: 極限突入／非突入）
   - チャージ回数
   - 極限バトル成功／失敗（成功率%表示）
   - 通常時計／LT中計
   - LT内訳: 7500初回／7500継続／1500継続／1500終了（各構成比%表示）

### 操作パネル（固定表示）

- **START**（丸型ボタン）: 1回転
- **1万円分回す**: 170回転を一括実行（当たり演出が出た時点で自動停止し、モーダルを閉じると再開）
- **⚙ 演出設定**: 上記の演出ON/OFF設定パネルを開く
- **退店する**: 精算画面（換金額・収支・出玉率などのサマリー）を表示し、「もう一度遊ぶ」でリロードして最初から

### 当たり演出

保留出現／剣出現／チャージ／BATTLE BONUS／極限バトル突入・JUDGEMENT／極限勝利・敗北／魔戒CHANCE／GOD OF GARO／1500継続／LT終了／精算 — いずれも全画面モーダルオーバーレイで表示。画像は`images/`から読み込み、失敗時はテキストプレースホルダーに自動フォールバックする。

### 遊技履歴

画面下部にスクロール式のログ欄。「◯回転目：〜」形式で各イベント（当たり・チャージ・追加投資）を新しい順に記録（最大150件保持）。

## 技術メモ

- 状態はページ内メモリ（`S`オブジェクト）のみで保持。DBやlocalStorageは使用しない。
- `newState()`はページ読み込み時（`DOMContentLoaded`）に一度だけ呼ばれ、即プレイ可能な状態になる。
- 演出モーダルは`showM()`/`closeM()`によるPromiseベースの逐次表示（`await showM(...)`のチェーンで進行を制御）。
- 演出ON/OFF判定は`getFigZone()`が毎回転ごとに`_swordOn`/`_holderOn`から動的に算出する（`both`/`holderOnly`/`swordOnly`/`yomi`の4モード）。
